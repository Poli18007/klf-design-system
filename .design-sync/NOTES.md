# design-sync notes — klf-design-system

Repo-specific gotchas for future syncs. Read this before re-running the sync.

## Where this repo came from

Extracted from `Poli18007/klf-group` (the KLF marketing site + dispatcher portal +
driver apps), where the same design system lives at `components/`, `tokens/` and
`styles.css`. Fixes made here do **not** flow back automatically — see "Fixes that
belong upstream" below.

## Shape and entry

- Source shape is `package`, not storybook: there is no `.storybook/` anywhere and
  no `*.stories.*` files.
- The components are plain **JSX with no TypeScript**, so there is no `.d.ts` tree
  for the converter to discover components from. Two consequences, both already
  handled in `config.json`:
  - `componentSrcMap` pins all 20 components explicitly. Without it the converter
    reports `[ZERO_MATCH] no component exports`. **A new component must be added
    to that map by hand** or it will not sync.
  - `dtsPropsFor` carries a hand-written props body for all 20, derived from the
    destructured parameters and the variant maps in each source file. Without it
    every component emits `ButtonProps { [key: string]: unknown }` and the design
    agent gets no API contract. Keep it in step with the sources.
- `--entry ./index.js` points at the barrel. `index.js` is generated from the
  component files; regenerate it when components are added.

## Tokens and CSS

- `cfg.tokensPkg` is the package itself (`klf-design-system`). `copyTokens` only
  reads from `node_modules/<pkg>`, so the repo must be linked into its own
  `node_modules` for the token files to ship:

  ```powershell
  New-Item -ItemType Junction -Path node_modules\klf-design-system -Target .
  ```

  **`npm install` prunes this junction** — recreate it after any install, or the
  build dies with `ENOENT ... node_modules/klf-design-system/package.json`.
- `cfg.cssEntry` points at `dist/global.css`, generated by `build-css.mjs` from
  `tokens/base.css` + `tokens/motion.css`. It exists because the components style
  themselves with inline styles, so there is no compiled component stylesheet; an
  `@import`-only `_ds_bundle.css` fails validation with `[CSS_PLACEHOLDER]`.
- `[FONT_REMOTE]` for Montserrat and JetBrains Mono is expected — `tokens/fonts.css`
  pulls them from a font host at runtime. Not an error.

## Fixed during the first sync (2026-09-15)

- **Broken CSS comment swallowed `--bsg-black`.** `tokens/colors.css` opened with a
  comment containing `--bsg-*/--gold-*`; the `*/` closed the comment early and the
  leftover text ate the next declaration. Every black surface in the system —
  `Button variant="solid"`, `Card inverse`, `SideNav`, `Toast`, `Tag selected`,
  checked `Checkbox` — rendered transparent, silently. Fixed by rewording the
  comment. **The same bug is still live in `klf-group/tokens/colors.css`.**
- **Logo pointed at artwork that does not exist.** It loaded
  `assets/logo-compact.png` / `logo-primary.png` / `logo-mono-black.png` (BSG-era
  filenames) and its alt text read "BSG Carriers"; the only artwork in either repo
  is `assets/klf-logo.png`. Repointed every variant at that file and fixed the alt
  text. The variants are therefore visually identical until separate cuts exist —
  a compact monogram-only cut and a reversed cut for dark surfaces are the gap.
  The KLF lockup has a dark wordmark, so it is a **light-surface** mark.
- **Icons depended on a network fetch.** `Icon` masked its glyph from
  `unpkg.com/lucide-static`, so every icon in every design would vanish wherever
  outside requests are blocked. `build-icons.mjs` now inlines 75 glyphs into
  `components/core/icon-data.js`; unlisted names still fall back to the CDN. Adding
  an icon means adding its name there and re-running the script.

## Preview authoring — what the first campaign learned

- **Nothing copies `assets/` into `ds-bundle/`.** The preview server roots at the bundle
  and 404s anything outside it, so a component that renders `<img src="assets/…">`
  shows a broken image in every card. That is why `Logo` is inlined via
  `build-logo.mjs` rather than path-wired: the mark now renders with no asset hosting
  anywhere, and `basePath` still switches back to a hosted file. Any future component
  that references a bundled image needs the same treatment.
- **Grid cells are ~380px wide**, not viewport width. Horizontal compositions (tab
  bars, button rows, badge rows) must be authored to fit that, unless the component
  carries `cardMode: "column"` (`DataTable`, `SideNav`, `Timeline`, `StatTile`,
  `Toast`, `Tooltip`, `Tabs` do) or `cardMode: "single"` (`Dialog`).
- **`[CONFIG_STALE]` trap:** adding `viewport` or `skip` to `cfg.overrides.<Name>`
  invalidates the stamped build and forces a full `package-build.mjs` run — the cheap
  targeted `preview-rebuild.mjs` loop refuses. Only `cardMode` and `primaryStory` ride
  the targeted loop. This blocked `Dialog` for a whole batch.
- **`var(--surface-card)` is the same white as the capture sheet**, so a card wrapper
  in a preview is invisible without an explicit `1px solid var(--border-default)`.
- **`Tooltip` cannot show its label in a static capture.** The label lives behind
  `useState` + `onMouseEnter` with no `open`/`defaultOpen` prop, so its four cells
  document the trigger compositions at rest. Making the label reviewable needs a
  component-source change.
- **`Dialog` scrim is `position:absolute; inset:0`**, so every preview wraps it in a
  sized `position:relative` parent or it collapses.
- **Don't put `Logo` on the black `SideNav` rail** — dark wordmark on black. The cells
  use a text header or a `Badge` instead, and footer buttons need `variant="ghost" inverse`.

## Component issues worth fixing upstream (found while authoring previews, not applied)

1. **`Input textarea` clips its last line.** The default `minHeight: 104` cuts off
   realistic multi-line content until the user drags the resize grip; previews pass
   `rows={6}` to work around it. Consider defaulting `rows` or raising `minHeight` —
   every consumer hits this.
2. **`Switch`'s off track is `var(--neutral-800)`**, which renders as pale grey despite
   the source comment implying a dark track. Legible on light surfaces; check it on
   dark ones, where it may disappear.
3. **No group container for `Checkbox`/`Radio`/`Switch`.** Every realistic use needed a
   hand-rolled card plus an uppercase group label. A `FieldGroup` primitive would remove
   that duplication and keep group labels consistent with `Input`/`Select`.
4. **`Toast` uses the Lucide name `check-circle`** while the rest of the system spells it
   `circle-check`. Both resolve (both are inlined), but the two spellings coexist.
5. **`Badge` has no inverse mode** — `Tag selected` is the nearest equivalent for dark
   surfaces.

## Known render warns

- `[RENDER_BLANK]` / floor-card warnings on any component with no authored preview
  are expected, not failures — that component just ships its typographic card.

## Fixes that belong upstream in `klf-group`

2. `Logo` artwork paths and alt text.
3. The CDN icon fetch, if the site should render icons offline.

## Re-sync risks

- **`componentSrcMap` and `dtsPropsFor` are hand-maintained.** A component added or
  a prop renamed upstream will not be noticed by the converter — it will silently
  sync the old contract. Diff `components/` against both maps when the source moves.
- **The `node_modules` junction is not in git** and is destroyed by `npm install`.
  A fresh clone must recreate it before the first build.
- **`index.js`, `dist/global.css` and `icon-data.js` are generated and committed.**
  If a component is added without regenerating them, the bundle and the barrel
  disagree and the new component is missing from `window.KLFDesignSystem`.
- **This repo is a copy, not a workspace of `klf-group`.** The two will drift.
  Decide deliberately which is the source of truth before the next sync.
- Preview stories under `.design-sync/previews/` compose the real components with
  realistic freight content; they need updating when a prop is renamed, or their
  cells will render wrong and the grade carried forward will be stale.
